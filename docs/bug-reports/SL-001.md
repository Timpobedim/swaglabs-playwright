# SL-001. Сумма товаров на шаге Overview выводится без округления до центов

| Поле | Значение |
|---|---|
| Серьёзность | Minor — ошибка отображения, налог и итог рассчитаны верно |
| Приоритет | Medium — видна любому покупателю, чья корзина даёт «неудобную» сумму |
| Окружение | https://www.saucedemo.com · Chromium 151 (Playwright 1.62, headless) · Windows 10 · 11.09.2026 |
| Пользователь | `standard_user` |
| Воспроизводимость | стабильно при указанном составе и порядке корзины |
| Автотест | `tests/customer/test_checkout.py::test_subtotal_is_rounded_to_cents` (xfail) |

## Шаги

1. Войти как `standard_user` / `secret_sauce`.
2. Добавить в корзину пять товаров именно в таком порядке: Sauce Labs Bike Light ($9.99),
   Sauce Labs Bolt T-Shirt ($15.99), Test.allTheThings() T-Shirt (Red) ($15.99),
   Sauce Labs Backpack ($29.99), Sauce Labs Fleece Jacket ($49.99).
3. Открыть корзину → **Checkout**, заполнить имя, фамилию и индекс → **Continue**.

## Ожидаемый результат

`Item total: $121.95`.

## Фактический результат

`Item total: $121.94999999999999`. Налог `$9.76` и итог `$131.71` при этом верные
(проверяет соседний тест `test_tax_and_total_are_correct_for_float_prone_cart`).

## Анализ

Цены складываются числами с плавающей точкой, а сумма выводится без форматирования до двух знаков.
Поэтому дефект зависит от набора и порядка цен: 9.99 + 15.99 + 15.99 + 29.99 + 49.99 в IEEE 754 даёт
121.94999999999999, а весь каталог в порядке A→Z ($129.94) и корзина из двух товаров ($39.98)
выводятся верно. Проверка оформления заказа на одной-двух типовых корзинах такой дефект пропускает.
Как нашли: в исследовательской сессии корзина собиралась после сортировки «по цене», затем из неё
убрали самый дешёвый товар; первая версия автотеста на полном каталоге дала XPASS, после чего
состав корзины был восстановлен точно.
